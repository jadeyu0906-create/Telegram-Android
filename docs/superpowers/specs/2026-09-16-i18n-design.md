# 多语言支持设计文档

**日期**: 2026-09-16
**作者**: Claude Opus 4.6
**状态**: 待审核

---

## 1. 概述

为 Telegram Android 二开项目的自定义页面（闪屏广告页、Web3 登录页）添加多语言支持，支持中文（简体/繁体）、韩文、日文、英文，未匹配语言默认回退到英文。

### 目标
- 自定义页面支持 5 种语言
- 与 Telegram 官方多语言系统独立运行，互不干扰
- 使用 Android 标准资源系统，零代码侵入
- 自动根据系统语言切换，未匹配语言回退到英文

### 非目标
- 不修改 Telegram 官方页面的多语言逻辑
- 不提供应用内语言切换功能（遵循 Android 规范）
- 不支持 5 种语言以外的其他语言

## 2. 架构设计

### 2.1 双语言系统并存

```
┌─────────────────────────────────────────┐
│         Telegram Android App            │
├─────────────────────────────────────────┤
│                                         │
│  ┌─────────────────────────────────┐   │
│  │   Telegram 官方页面              │   │
│  │   (LaunchActivity, LoginActivity)│   │
│  │   使用: LocaleController         │   │
│  │   语言数: 100+                   │   │
│  └─────────────────────────────────┘   │
│                                         │
│  ┌─────────────────────────────────┐   │
│  │   自定义页面                     │   │
│  │   (SplashAdActivity,             │   │
│  │    Web3LoginActivity)            │   │
│  │   使用: Android 资源系统         │   │
│  │   语言数: 5 (en, zh-CN, zh-TW,   │   │
│  │             ko, ja)              │   │
│  └─────────────────────────────────┘   │
│                                         │
└─────────────────────────────────────────┘
```

### 2.2 语言匹配流程

```
用户系统语言设置
    ↓
Android 系统检测 (Locale)
    ↓
资源目录匹配规则：
    1. 完全匹配 (zh-CN → values-zh-rCN)
    2. 语言匹配 (zh → values-zh-rCN)
    3. 默认回退 (其他 → values)
    ↓
自定义页面显示对应语言
```

**匹配示例：**
- 用户系统语言: `zh-CN` (简体中文) → `values-zh-rCN/` → 显示简体中文
- 用户系统语言: `zh-TW` (繁体中文) → `values-zh-rTW/` → 显示繁体中文
- 用户系统语言: `ko` (韩文) → `values-ko/` → 显示韩文
- 用户系统语言: `ja` (日文) → `values-ja/` → 显示日文
- 用户系统语言: `fr` (法文) → `values/` → 显示英文（默认）

## 5. 布局文件修改

### 5.1 修改原则

将布局文件中所有硬编码的文本替换为 `@string/xxx` 引用。

### 5.2 需要修改的文件

1. `TMessagesProj_App/src/main/res/layout/activity_splash_ad.xml`
2. `TMessagesProj_App/src/main/res/layout/activity_web3_login.xml`

### 5.3 修改示例

**修改前：**
```xml
<TextView
    android:text="跳过广告 3s"
    ... />
```

**修改后：**
```xml
<TextView
    android:text="@string/splash_skip_ad"
    ... />
```

**注意：** 倒计时数字（如 "3s"）需要在 Java 代码中动态拼接，不能硬编码在字符串资源中。

## 6. Java 代码修改

### 6.1 SplashAdActivity.java

**需要修改的地方：**

1. **跳过按钮倒计时文本：**

**已使用动态资源加载，无需修改。**

布局文件中的文本替换为 `@string/xxx` 后，系统会自动根据语言加载对应的字符串资源。

## 8. 上游同步兼容性

### 8.1 冲突风险分析

**无冲突风险：**
- 所有资源文件位于 `TMessagesProj_App/src/main/res/`
- 不修改 `TMessagesProj/` 官方源码
- 不依赖官方的 `LocaleController`

### 8.2 同步注意事项

在执行 `git fetch upstream` 和 `git merge upstream/master` 时：
- 自定义资源目录（`values-*/`）不会与官方冲突
- 布局文件（`activity_splash_ad.xml`, `activity_web3_login.xml`）是自定义文件，官方不会修改

## 9. 维护指南

### 9.1 添加新文本

**步骤：**
1. 在 `values/strings.xml` 中添加新的 key（英文）
2. 在其他 4 个语言目录中添加相同 key 的翻译
3. 在布局文件或代码中引用 `@string/new_key` 或 `getString(R.string.new_key)`

### 9.2 修改现有翻译

**步骤：**
1. 找到对应语言目录下的 `strings.xml`
2. 修改对应 key 的文本内容
3. 提交到 git（提交信息：`chore: 更新XX语言翻译`）

### 9.3 添加新语言

**步骤：**
1. 创建新的语言目录（如 `values-de/` 德文）
2. 复制 `values/strings.xml` 到新目录
3. 翻译所有字符串
4. 测试验证

## 10. 技术决策记录

### 10.1 为什么选择方案 A（标准 Android 资源系统）？

**原因：**
1. 符合 Android 最佳实践
2. 与项目二开规范一致（代码隔离在 `TMessagesProj_App/`）
3. 零代码侵入，纯配置
4. 自动回退机制（未匹配语言显示英文）
5. 与官方系统完全隔离，无冲突风险

### 10.2 为什么不使用方案 B（混合官方 API）？

**原因：**
1. 自定义页面的文本几乎全是业务相关内容（"u多担保"、"多签公证"等），官方没有对应翻译
2. 引入 `LocaleController` 依赖会增加代码复杂度
3. 官方 API 可能随版本变化，增加维护成本
4. 收益不明显（节省的翻译工作量很少）

### 10.3 为什么支持简体和繁体中文？

**原因：**
1. 用户明确要求（"C. 简体和繁体都要"）
2. 中国大陆、台湾、香港用户使用习惯不同
3. 专业应用应尊重不同地区的语言习惯
